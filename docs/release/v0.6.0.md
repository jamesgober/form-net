# form-net v0.6.0 - Optimisation

**Date:** 2026-10-29
**Compare:** [`v0.5.0...v0.6.0`](https://github.com/jamesgober/form-net/compare/v0.5.0...v0.6.0)

**Measured, and faster.** v0.6.0 measures form-net against the other Rust form parsers on every benchmark family of the plan, publishes the numbers in `docs/PERFORMANCE.md`, and optimises against them. Behaviour is unchanged; every check is still on.

## Results

At least 20% faster than the best other Rust crate in every family, on every input but one:

- urlencoded to pairs, against form_urlencoded: 1.39x to 9.55x; level on a 25-byte two-field search query, where both crates spend their time on the same allocation.
- urlencoded to a struct, against serde_urlencoded and serde_qs: 1.59x.
- urlencoded serialize, against form_urlencoded: 2.26x.
- multipart streaming, against multer: 1.32x to 4.97x at every chunk size, the adversarial shapes included.
- multipart buffered, against multer and multipart: 1.36x to 2.31x.
- multipart to disk, against multipart: 2.09x.

Throughput: about 13.8 GB/s on a 100 MiB file part, 18.5 GB/s on 1 MiB of CR bytes, 3.9 GB/s decoding a fully escaped urlencoded body. The multipart parser makes one allocation per parse and none per chunk.

## What changed

- **The delimiter search** skips to the next CRLF 32 bytes at a time in safe Rust and compares the delimiter whole there; the automaton runs only near a chunk's end, so events stay identical for every split.
- **urlencoded** scans with a byte set that narrows as it learns, decodes escapes in place, validates UTF-8 once per body, and serializes escapes from a table.
- **Wipes** cover the bytes that were written instead of whole buffers, and growing buffers start small. Every written byte is still wiped; tests over caller buffers prove it.
- **`benches/`**: the benchmark crate, in its own workspace so the competitors never enter form-net's dependency tree, with tests that every driver does the same work. CI keeps it building.
- **`docs/PERFORMANCE.md`**: method, machine, every comparison, the plan's targets, allocation counts, and a capability comparison checked against each competitor's source.

## Verification

- Every earlier test, property test, and fuzz target, plus new tests for the narrower wipes (caller buffers must read all zeros after drop), the growth bound near a buffer's cap, and the scanner against a naive search.
- An independent review of the optimisations, with differential tests of the new matcher, scanner, decoder, and encoder against the old code; its findings are fixed with regression tests.
- Fuzz targets for every changed path run clean locally; every target runs for 60 seconds in CI.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.
