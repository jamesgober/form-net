# form-net v0.2.0 - Design Lock

**Date:** 2026-10-23
**Compare:** [`v0.1.0...v0.2.0`](https://github.com/jamesgober/form-net/compare/v0.1.0...v0.2.0)

**The public API, written down before the code.** v0.2.0 locked every name, signature, behaviour, and error of form-net from `0.3.0` to `1.0.0` in [`docs/API.md`](https://github.com/jamesgober/form-net/blob/main/docs/API.md), and checked it against what each consumer crate needs. There is no parsing code in this release; `0.3.0` builds the core against this contract. It is also the first release on crates.io.

## What's in 0.2.0

- **`docs/API.md`.** Every public item, #1 to #73: form kind detection; urlencoded parsing (owned, borrowed, allocation-free into a caller buffer, and streaming) and serializing; buffered and streaming `multipart/form-data`; file name views that are never used as paths; `Limits` and `Policy`; the `Inspector` and `Sink` hooks and the driver that guarantees their order; temporary-file storage with anonymous and named modes and a pluggable disk budget; blocking readers; typed extraction without serde (`form!`, `FromForm`, `FromField`, `Secret`, `FileData`); the multipart writer; and one `Copy` error type with status hints and stable codes. Each item carries its grade, tier, version, feature, behaviour, errors, cost target, and examples.
- **Strict by default.** The document lists every place form-net refuses what the WHATWG and RFC texts would repair or tolerate (malformed `%`, invalid UTF-8, bare LF, transfer encodings, nested multipart, both file name parameters, `\"` in quoted values, `filename*`), and the opt-in for each leniency that has one.
- **Consumer checklists.** Tables for web-net, customs-sec, csrf-sec, and outbound clients map each need to the item that serves it: one line to read a typed form whichever encoding the browser used, inspection in the same pass as parsing, and the anti-forgery token captured before any file reaches the disk.
- **`dev/PLAN.md`.** The design rewritten from the specification: requirements, the enterprise and distributed section, the urlencoded and multipart engines (a SWAR scan and a streaming Knuth-Morris-Pratt delimiter matcher that never rescans), budgets with a worst-case memory formula, storage per platform, threats T-1 to T-38 with their defences, tests, and costs, performance targets against `multer`, `form_urlencoded`, `serde_urlencoded`, `serde_qs`, and `multipart`, and the testing plan.
- **Decisions D-004 to D-073.** Every open question of the specification decided (the serde adapter stays open until after 1.0), and the changes made at the lock: plain names without abbreviations, a consistent `_with` / `_inspected` naming, `from_body` for either encoding, configuration errors that never look like a client's 413, stable error codes, an inspector hook that hears every refusal, a disk budget behind a trait, limits where the containing one caps the rest (so a route sets only what it cares about), buffer sizes as `const fn`s, and no global state.
- **`dev/ROADMAP.md`.** Every version from 0.1 to 1.0 with its items and exit criteria.

## Verification

- An independent review of the three documents; its 22 findings (examples that would not compile, buffer sizing, version gates, naming) were fixed before the release.
- Every item in the index is assigned to exactly one version in the roadmap, with the same version in both; every decision referenced exists in the log.
- Local gate on Windows and WSL Ubuntu, stable and 1.85: format, clippy in three feature modes, tests in three modes, documentation with default and all features, and `cargo package` in a fresh target directory.
- Banned-content scan clean; links and anchors in the documentation checked.
- CI green on every platform before the tag.

## What's next

`0.3.0` ships the core: detection, urlencoded parsing and serializing, the boundary, the streaming multipart parser with its part headers and file name views, limits, policies, and errors, on parse-net's grammar, with tests on every path, standards cases split at every byte, property tests, counting-allocator tests, a reference-parser differential, fuzz targets, and a bare-metal `no_std` build.
