# form-net v0.4.0 - Extended

**Date:** 2026-10-23
**Compare:** [`v0.3.0...v0.4.0`](https://github.com/jamesgober/form-net/compare/v0.3.0...v0.4.0)

**Uploads, inspection, and typed forms.** v0.4.0 adds what a server needs on top of the 0.3 parsers: files stored safely while the body streams in, hooks that let an inspector refuse content before anything is stored, blocking readers, and typed extraction with one declarative macro.

## What's in 0.4.0

- **Upload storage (feature `fs`).** `read_multipart(content_type, body)?` for any `Read`; `UploadSession` for chunks pushed by an async server; `Upload::parse_with` for explicit limits, policy, store, and inspector. Small files stay in memory; larger ones go to temporary files in a private directory (`form-net-` plus 128 random bits, 0700), with random names, `create_new`, and 0600. In the default anonymous mode a file has no name at all (unlinked on Unix, delete-on-close on Windows), so a killed process leaves nothing behind. Every file is deleted on drop, on abort, and on any error; `persist` never overwrites; `max_disk_bytes` caps one request.
- **Inspection hooks.** An `Inspector` sees every part head, the first `sniff_bytes` of every file, every data chunk, and every text field, in a fixed order at every split of the body, and can continue, skip, or refuse with its own status and code. Inspectors chain: `(customs, app)` runs both in one pass.
- **Storage hooks.** A `Sink` decides where file bytes go; the `Driver` runs parser, inspector, and sink together and opens the sink only after the inspector has accepted the part, so a refused upload never reaches storage.
- **Token first.** With `TokenField`, a file that arrives before the anti-forgery token is refused at its first header, and `UploadSession::captured_token` returns the token as soon as its part ends, so a forged upload is dropped before it costs disk.
- **Blocking readers.** `MultipartReader` and `PartReader`: ask for the next part, read it like a file, save it to a store.
- **Typed forms.** `form!` declares a struct and its `FromForm` implementation; `from_body` reads either encoding. Unknown, repeated, missing, and invalid fields are refused, and errors name the field without echoing input. Field types: `String`, the integers (strict), finite floats, `bool` (checkbox), `char`, `Option`, `Vec`, `Secret`, `FileData`, `StoredFile`.
- **Secrets.** Owned values are now wiped with crypt-io's volatile wipe over the whole allocation, on success and on every error path, including file names and the reader and driver buffers. This brings the audited `zeroize` and `subtle` under `alloc`; the allocation-free core still depends on parse-net alone.

## Verification

- Storage tests on Windows, Linux, and macOS: memory and spill thresholds, permissions, anonymous and named modes, persist without overwrite, disk limits, planted files and links, concurrent readers.
- Abort at every byte of a 3-file body in both modes: no file left, and no open handle on Linux. A child process killed mid-upload leaves no anonymous file.
- The hook order at every split, through the driver, the buffered parser, and the urlencoded parser; a refusal from each hook calls `failed` once and touches no storage.
- Attack tests for every 0.4 threat in `dev/PLAN.md`, and a test-only counter proving every owned value wipes all its bytes on drop.
- Ten fuzz targets, the two new ones (`fuzz_extract`, `fuzz_upload_session`) run clean locally and every target run for 60 seconds in CI.
- An independent review of the 0.4 code, and a review of the `Inspector` and `FromForm` shapes against the customs-sec and web-net plans; every finding fixed or scheduled with a recorded reason (D-083 to D-090).
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.

## What's next

`0.5.0` completes the feature set: the multipart writer, the shared disk budget across requests, `sweep` for named mode, `memory_bound` for admission control, the `unicode` feature (NFC file names), and the extraction shapes the consumer review asked for.
