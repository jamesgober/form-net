# form-net v0.11.0 - Review

**Date:** 2026-11-11
**Compare:** [`v0.10.0...v0.11.0`](https://github.com/jamesgober/form-net/compare/v0.10.0...v0.11.0)

**An independent review of the whole crate, and every finding fixed.** A reviewer read form-net 0.9.2 against its own claims: 1 medium, 8 low, and 3 notes, no critical or high. The limits, the multipart framing, split invariance, traversal handling, and temporary-file creation held. Each finding now has a regression test, and each is fixed (D-149 to D-161).

## The medium finding

`FileName::sanitized` kept the first 255 bytes of a long name. A 259-byte `A…A.php.jpg` passed an `extension() == Some("jpg")` check and was saved as `A…A.php`. Now a long name loses bytes from the end of its stem, never its extension, so the name the check saw is the name saved (D-156).

## Migrating from 0.10

| 0.10 | 0.11 |
|---|---|
| `file.persist(&dest)?` | unchanged: `?` converts the new error into `FormError` |
| `match file.persist(&dest) { Err(e) => .. }` with `e: FormError` | `e: PersistError`; `e.error()` is the `FormError`, `e.into_file()` gives the upload back |
| a body reader's failure as `FormError::Io { kind }` | `FormError::BodyRead { kind }` (400); `Io` stays the writer and the file system (500) |
| `application/x-www-form-urlencoded; charset=us-ascii` accepted | refused with `UnsupportedCharset`, like any charset other than UTF-8 |

## What changed

- **`persist` keeps the upload when it fails** (D-154). The documented advice for an existing destination, "choose another name", was impossible: every error path dropped the file. `PersistError::into_file` hands it back, and a named spill is reopened first, so it reads and persists again.
- **Persisted files are owner-only on Unix** (D-155), whether `persist` linked or copied them; widen them after `persist` if others must read them.
- **`sweep` reaches crash leftovers under `Store::temp`** (D-158): it goes one level into the `form-net-<32 hex>` directories under the directory it is given, never through a link, and removes old spill files there. The directories stay, since a live store may own one.
- **Dot files** (D-157): `sanitized` replaces a leading `.` with `_`, and `extension` of `.htaccess` is `None`.
- **`us-ascii` text must be ASCII** (D-150). WHATWG readers decode the label as windows-1252, so a byte at or above 0x80 read differently there.
- **File names holding `name=`** (D-152): 0.9.1 refused any parameter value holding `name=`, which failed real uploads such as `Surname=Smith.pdf`. Only the positions where a splitting reader takes it for a parameter are refused now: the start of the value, or after `;`, `,`, or whitespace. Each shape was checked by running multer 3.1.0.
- **A client disconnect is a 400** (D-159): `FormError::BodyRead`.
- **Docs** (D-151, D-153, D-160): the parser and architecture claims say what the code does (the hook order is `part_end` before `close`), every public item has a runnable example, and `memory_threshold` says it changes nothing on a memory-only store.

## Not changed, with the reason

The three performance notes (D-161). Each would trade memory or a copy for a syscall, with no measured need. parse-net's finding that `filename*` wins over `filename` does not reach form-net: it reads `Content-Disposition` itself and refuses a part with both.

## Verification

- `tests/review_independent.rs` and `tests/store.rs`: one test per finding, each failing on 0.10.0; `sanitized` against `extension` for every length from 240 to 300 bytes.
- Every existing test, doctest, bench driver, and fuzz target passes.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.

## Not in this release

The release-candidate exit is unchanged: customs-sec as the real `Inspector` and two weeks on a deployed site.
