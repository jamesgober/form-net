# form-net v0.10.0 - Simplicity

**Date:** 2026-11-11
**Compare:** [`v0.9.2...v0.10.0`](https://github.com/jamesgober/form-net/compare/v0.9.2...v0.10.0)

**One name for each thing, before 1.0 fixes the names.** v0.10.0 checked the public API against one rule: a common use is one obvious call, and a newcomer can read the names without the docs. Tier 1 already met it: `parse_urlencoded`, `parse_query`, `serialize_urlencoded`, `parse_multipart`, `read_multipart`, and `form!` with `from_body` are one call each with plain `?`. Four places did not, and they are fixed here. It is a breaking release; migrating is a matter of renames, listed below (D-148).

## Migrating from 0.9

| 0.9 | 0.10 |
|---|---|
| `form.get(name)` | `form.field(name)` |
| `form.get_one(name)` | `form.field_one(name)` |
| `form.get_all(name)` | `form.fields(name)` |
| `Upload::parse_with(ct, body, &limits, &policy, &store, &mut inspector)` | `form_net::read_multipart_inspected(ct, body, &limits, &policy, &store, &mut inspector)` |
| `Upload::parse_with(ct, body, &limits, &policy, &store, &mut NoInspector)` | `form_net::read_multipart_with(ct, body, &limits, &policy, &store)` |
| `form_net::Step`, `form_net::Event` | `form_net::MultipartStep`, `form_net::MultipartEvent` |
| `ExtendedFilenamePolicy::Ignore` | `ExtendedFilenamePolicy::Refuse` (the same refusals since 0.9.2) |

Each is a rename: the arguments, the results, and what is accepted or refused are unchanged. web-net needs no change.

## What changed

- **One lookup, one name.** `Multipart` and `Upload` looked fields up with `field`, `field_one`, and `fields`, and `Form` with `get`, `get_one`, and `get_all`. `Form` now uses the same three names.
- **One pattern per entry point.** Every entry point comes as `X`, `X_with` (limits and policy), and `X_inspected` (an inspector as well), except the blocking upload reader, which was `Upload::parse_with`. It is now `read_multipart_with` and `read_multipart_inspected`, beside `read_multipart`.
- **Types named by their parser.** The urlencoded parser's step and event types were `UrlencodedStep` and `UrlencodedEvent`, but the multipart parser's were plain `Step` and `Event`. They are now `MultipartStep` and `MultipartEvent`.
- **One policy per behaviour.** `ExtendedFilenamePolicy::Ignore` has refused exactly what `Refuse` refuses since 0.9.2 (D-147), so it is removed.
- **`docs/API.md`** takes the reference layout of the other crates: header and navigation, tiers, every public item with its errors, costs, and examples, and an index of public items.

## Kept, with the reason

- `FromForm::from_multipart`, beside `from_body`: it refuses a urlencoded body, which is how an upload-only route says so.
- `parse_urlencoded_with` beside `parse_urlencoded_inspected`, and so on: tiers of one call, not two ways to make it.
- `pairs` beside `parse_urlencoded`: it iterates without building a `Form`.

## Verification

- Every test, doctest (every example in `docs/API.md` included), and bench driver passes on the renamed API; the fuzz targets build and run on it.
- No slowdown: the renames and the moved function compile to the same code.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.

## Not in this release

The release-candidate exit is unchanged and now counts from 0.10.x: customs-sec as the real `Inspector` and two weeks on a deployed site.
