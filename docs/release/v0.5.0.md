# form-net v0.5.0 - Feature complete

**Date:** 2026-10-26
**Compare:** [`v0.4.0...v0.5.0`](https://github.com/jamesgober/form-net/compare/v0.4.0...v0.5.0)

**Every item of the design is in.** v0.5.0 adds the last P2 items: streaming urlencoded, the client side, shared disk budgets with crash cleanup, admission-control bounds, NFC file names, and the extraction shapes the customs-sec and web-net review asked for.

## What's in 0.5.0

- **Streaming urlencoded.** `UrlencodedParser` takes chunks of any size over a caller scratch buffer and returns the same pairs, and the same errors at the same offsets, for every split. A sequence too long for its budgets is refused as soon as its first bytes prove it, so the scratch never overflows.
- **The client side.** `MultipartWriter` writes `multipart/form-data` as browsers do, with a generated 128-bit boundary or the caller's. Every body it produces parses back with form-net to the same fields: names and file names are escaped by the browser rule, and anything that could read back differently (control bytes, a backslash in a name, a literal `%22`, a `multipart/*` content type, a delimiter inside the data) is refused before a byte is written. `encode_part_head` does the same into a caller buffer, without allocating.
- **Shared disk budgets.** `Store::quota(SpillQuota::new(bytes))` bounds the disk used by every request through every store that shares the quota; the request that would cross it gets a 503 hint. `SpillBudget` is the seam for a budget over several processes or a fleet. One quota per tenant keeps one tenant from filling the disk for the others.
- **Crash cleanup.** `sweep(dir, older_than)` removes the named-mode spill files a crash left behind, only names form-net makes, never following links.
- **Admission control.** `Limits::memory_bound` and `Store::memory_bound` give the worst-case memory of one request, measured against hostile bodies and against 1,000 uploads in flight at once.
- **NFC file names.** Feature `unicode`: `FileName::nfc`, and `sanitized` normalizes first, so an NFD name from a macOS client sanitizes to the same bytes.
- **Extraction.** `from_body_all` returns every field's error at once, for showing a form again; `from_upload_mut` fills a struct and leaves the rest of the upload usable; `Upload::from_form(form, &policy)` gives one owned type for both encodings, capturing the anti-forgery token as a multipart parse does.
- **Docs.** `docs/ARCHITECTURE.md` and `docs/PLATFORM-NOTES.md` (temporary files per platform, persist, fsync, crash behaviour); every example in `docs/API.md` now compiles and runs as a test.

## Verification

- Property tests: the writer round trip (every accepted input parses back to the same fields), streaming urlencoded split invariance against `raw_pairs`.
- A peak-tracking allocator holds `memory_bound` against hostile bodies at every chunk size, and 1,000 concurrent uploads within 1,000 times the bound (T-33).
- Shared budget under 16 threads of parallel uploads: never over the limit, every reserved byte released (T-7); a `loom` model of `SpillQuota` in CI.
- A killed child process in named mode leaves its file, and `sweep` removes it (T-11); header injection through the writer refused (T-34); delimiter in client data refused at every split (T-35).
- Twelve fuzz targets, the two new ones (`fuzz_urlencoded_stream`, `fuzz_writer_roundtrip`) run clean locally, every target for 60 seconds in CI.
- An independent review of the 0.5 code; findings fixed before the tag.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.
