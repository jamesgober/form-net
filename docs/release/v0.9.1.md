# form-net v0.9.1 - Review

**Date:** 2026-11-08
**Compare:** [`v0.9.0...v0.9.1`](https://github.com/jamesgober/form-net/compare/v0.9.0...v0.9.1)

**The adversarial review before 1.0.** v0.9.1 is the first freeze candidate. Three independent reviews attacked the crate, one area each: the multipart core, the driver and storage, and the urlencoded, extraction, and writer code. They found 18 defects, one of them high. Each came with a failing test, and each is fixed so that its test passes (D-136 to D-146). web-net runs the first site's routes on 0.9.0 and needed no API change (D-134).

## The high finding

`multipart/form-data; boundary=X; boundary*=UTF-8''Y` was accepted, and the body was framed with `X`. Go's `mime.ParseMediaType` lets the starred value win and frames it with `Y`. A body can then hold one form for a Go proxy or WAF in front and another for form-net behind it. Any starred parameter in the request `Content-Type` is now refused (D-136).

## Refused now (D-136)

Every one of these was checked against the reader that disagrees, and no browser sends any of them:

- An empty parameter (`;;`) in the request `Content-Type`, a part `Content-Type`, or `Content-Disposition`. Go refuses the whole parameter list, so `net/http` skips the part.
- A `Content-Disposition` parameter value that holds `name=`, such as `x="y;name=evil;"`. multer 3.1 finds parameters by substring search and reads another name there.
- A boundary that starts or ends with `'`, in `Boundary::new`, so the writer cannot send one either.

## Changed

- A file field given a real file and an empty file input under one name is `Duplicate` (D-137). `FileData`'s and `StoredFile`'s `FromField::Slot` is now `(bool, Option<T>)`.
- `form!` does not compile two fields with one wire name, or a field that is also ignored; the second field could never receive a value (D-138).
- `MultipartReader::next_part` reads the epilogue before it returns `None`, so `max_epilogue_bytes` holds there as in `parse_multipart` (D-142).

## Fixed

- A `part_end` refusal now aborts the sink instead of closing it. A sink that commits on close no longer keeps a file the inspector refused (D-139).
- The driver's copy of a part head no longer passes `memory_bound` (D-140).
- A second `_charset_` field reads the same in the buffered parser, `UploadSession`, and `PartReader::text` (D-141).
- An aborted spill keeps its quota while its file could not be deleted (D-143).
- `Upload::parse_with` calls `Inspector::failed` on a setup error (D-144).
- A body with two errors reports the same one however it was split (D-145).
- `Pairs` and `Serializer` `Debug` no longer show the body (D-146).

## Drafted

`docs/STABILITY-1.0.md`: what 1.0 will promise. Beyond the signatures, it fixes how bodies are read: an accepted body reads the same in every 1.x release, a refusal is never loosened, and a new refusal is allowed only for a construct two readers read differently.

## Verification

- `tests/review_multipart_core.rs`, `tests/review_driver_store.rs`, and `tests/review_urlencoded_extract.rs`: one test per finding. Each failed on 0.9.0 and passes now.
- The capture corpus (Chrome, Edge, Firefox, Safari, curl, requests, Go), the mutation generator, and every split test pass unchanged.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.

## Performance

Measured against 0.9.0 on the same machine, alternating three times (the machine was loaded, so these are comparisons, not absolute numbers):

- `FormKind::detect`: about 30 ns more per request (173 to 184 ns, now 200 to 213 ns). It counts the `;` bytes and searches for `*`, and runs the full checks only when one of them finds something.
- Every multipart row is level within the run-to-run spread: 100 parts, the 100 MiB file, the adversarial shapes, and the 1-byte split.
- The fixes on the error paths (the body limit, charging data before a framing error) cost nothing on a valid body.

## Not in this release

The v0.9.x exit needs customs-sec as the real `Inspector` and two weeks on a deployed site. One item is left for James in `dev/READINESS-1.0.md`: refusing a part with only `filename*` under the opt-in `ExtendedFilenamePolicy::Ignore`.
