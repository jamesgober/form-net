# form-net v0.9.2 - Ignore

**Date:** 2026-11-09
**Compare:** [`v0.9.1...v0.9.2`](https://github.com/jamesgober/form-net/compare/v0.9.1...v0.9.2)

**The last review finding, decided.** The 0.9.x adversarial review found that under the opt-in `ExtendedFilenamePolicy::Ignore`, a part with only `filename*` was read as a text field, while an RFC 2231 reader (Go's `mime/multipart`, an inspection layer in front) reads it as a file. 0.9.1 left this open because `Ignore` came from an earlier decision (D-014). It is decided now: the part is refused (D-147).

## Changed

- Under `Ignore`, a part with only `filename*` is refused with `Policy { ExtendedFilename }`, as under `Refuse`.
- `ExtendedFilenamePolicy::Ignore` is deprecated. A part with both `filename` and `filename*` was already refused under every policy, so `Ignore` now refuses exactly what `Refuse` refuses. The variant stays, so a configuration that names it still compiles, with a deprecation warning that points to `Refuse`.

Nothing changes under the default policy (`Refuse`) or under `AcceptAlone`, and no browser sends `filename*`.

## Verification

- `test_ignore_policy_refuses_a_part_with_only_extended_filename` (`tests/review_multipart_core.rs`) failed on 0.9.1 and passes now. A plain `filename` still makes a file under `Ignore`.
- Local gate on Windows and WSL Ubuntu, stable and 1.85; CI green on every platform before the tag.

## Not in this release

The v0.9.x exit is unchanged: customs-sec as the real `Inspector` and two weeks on a deployed site.
